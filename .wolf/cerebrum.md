## Key Learnings

- **Project:** elgg-migrate
- **Description:** Automated migration toolkit for upgrading Elgg CMS plugins across major versions (2.x through 7.x).
- [2026-04-14] **Elgg 4.x core plugins live in `vendor/elgg/elgg/mod/`**, not `/var/www/html/mod/`. The plugin loader only scans `mod/`, so any plugin declaring a core dep (`search`, `blog`, ...) in `plugin.dependencies` fails to resolve in a per-plugin docker stack unless the install script symlinks each `vendor/elgg/elgg/mod/*` into `mod/` before `generateEntities()`. Template at `skills/elgg-test-writer/templates/elgg4/elgg-install.sh`.
- [2026-04-14] **`\Elgg\HooksRegistrationService\Hook` constructor in 4.x** is `__construct(PublicContainer $dic, $name, $type, $value, $params)`. First arg is `elgg()` (not `elgg_services()->hooks`). Arg order changed from 3.x — `$value` (return value) comes BEFORE `$params`. In tests: `new Hook(elgg(), 'route', 'type', $value, [])`. `\Elgg\Hook` is an interface and cannot be instantiated.
- [2026-04-14] **`\Elgg\HooksRegistrationService\Hook` phpunit require-dev**: The elgg4 Docker image was built before `phpunit/phpunit ^9.6` was added to `elgg-composer.json`, so `vendor/bin/phpunit` didn't exist. Install with `composer require --dev phpunit/phpunit:'^9.6'` inside the container, or rebuild the image.
- [2026-04-14] **`ElggPlugin::setPriority()` in Elgg 4.x** accepts `int`, `'+N'`, `'-N'`, `'first'`, `'last'` — **not** `'after'`/`'before'`. To satisfy `plugin.dependencies` position-after at activation time, call `setPriority('last')` before `activate()`. Passing `'after'` returns the unchanged priority silently and activation still fails.
- [2026-04-15] **Elgg 4.x CSS/JS registration pattern**: register CSS via `elgg_register_external_file('css', $handle, $url)` in Bootstrap `init()`; load in views via `elgg_load_external_file('css', $handle)`. The old `elgg_register_css`/`elgg_load_css` wrappers were removed entirely.
- [2026-04-15] **`elgg_require_css($view)` in Elgg 4.x** auto-resolves a CSS view name to a simplecache URL — it does NOT work with registered CSS handles. Don't confuse it with the old `elgg_load_css($handle)`.
- [2026-04-15] **Composer `installer-name` must be lowercase** in Elgg 4.x — set `extra.installer-name` to the lowercase plugin directory name (e.g. `hypedbexplorer`), not `hypeDBExplorer`.
- [2026-04-15] **`ActionsService::getAction()` does not exist in Elgg 4.x** — use `elgg_action_exists($action)` for existence check; use `_elgg_services()->actions->getAllActions()` to get an array with `access` keys for admin/logged_in/public.
- [2026-04-15] **`elgg_instanceof()` does not exist in Elgg 4.x** — replace with `$entity instanceof \ElggObject && $entity->getSubtype() === 'subtype'`.
- [2026-04-15] **`get_input()` in Elgg 4.x does NOT read from `$_REQUEST`** — it reads from the Elgg Request service. In integration tests, use `set_input('key', 'value')` to set input before calling `get_input()`.
- [2026-04-15] **`ElggFile::save()` requires a logged-in user** — saving an `ElggFile` (or subclass) without a session returns false. In integration tests, call `elgg_get_session()->setLoggedInUser($user)` before `$file->save()`.

- [2026-04-14] **`elgg_set_plugin_setting()` does not exist in Elgg 4.x** — use `$plugin = elgg_get_plugin_from_id('pluginid'); $plugin->setSetting('key', 'value')` instead.

## Key Learnings

- [2026-04-15] **`theme_sandbox` is NOT in the production `elgg/elgg` Composer package** — it's a dev-only plugin in the Elgg source repo and never ships in `elgg/elgg ^4.x`. Playwright tests that rely on the theme sandbox route will fail in any standard Docker test stack. Rewrite E2E tests to use core Elgg pages (login, homepage) instead.
- [2026-04-15] **Elgg 4.x login page renders two login forms** — a hidden header dropdown (`#login-dropdown-box`, CSS `display:none`) and a visible sidebar form (`.elgg-module-aside`). `page.fill('input[name="username"]')` hits the hidden dropdown first (DOM order). Always target `.elgg-module-aside input[name="username"]` for Playwright login.
- [2026-04-15] **Playwright `baseURL` must be inside `use:{}` block** — setting it at the `defineConfig` root level is silently ignored in Playwright ≥1.50. Result: `page.goto('/login')` throws "Cannot navigate to invalid URL".
- [2026-04-15] **Per-plugin Docker stack must use `ELGG_SITE_URL: http://elgg/`** (the internal Docker service hostname), NOT `http://localhost:PORT/`. After login, Elgg redirects to `wwwroot`. If wwwroot uses `localhost:PORT`, the Playwright node container can't follow the redirect and gets `chrome-error://chromewebdata/`.
- [2026-04-15] **`elgg-install.sh` is baked into the Docker image** via `COPY` in the Dockerfile. Changes to the host install script only take effect after `docker compose build --no-cache elgg`.
- [2026-04-15] **Playwright image version must match `@playwright/test` package version** — `mcr.microsoft.com/playwright:v1.49.0-noble` only has browsers for Playwright 1.49.x. If `package-lock.json` resolves to 1.59.1, use `mcr.microsoft.com/playwright:v1.59.1-noble`.

- [2026-04-20] **`elgg/init` AMD module removed in Elgg 4.x** — any `require('elgg/init')` in an AMD module causes a 403 script error and silently prevents the whole module from executing. Drop this require entirely; Elgg 4/5.x handles init differently. Symptom: module never appears in `require.s.contexts._.defined`.
- [2026-04-20] **`elgg.echo()` removed from the `elgg` AMD module in Elgg 4.x** — `elgg.echo('key')` throws "elgg.echo is not a function". Add `var i18n = require('elgg/i18n');` and call `i18n.echo('key')` instead.
- [2026-04-20] **`elgg.provide()` removed in Elgg 4.x** — `elgg.provide('elgg.ui.lightbox')` throws "elgg.provide is not a function". Replace the `elgg.provide` + `deprecated_settings` pattern with a plain `$.extend(settings, opts)`.
- [2026-04-20] **Playwright AMD readiness check**: use `require.s.contexts._.defined['elgg/modulename']` to poll for a module being in-registry without triggering a re-fetch. `require.defined()` and `require([...], cb)` both attempt dynamic script loads which fail in isolated test stacks.
- [2026-04-22] **`\DI\object()` removed in PHP-DI v6** (Elgg 4.x uses v6). Replace with `\DI\create()`. The `->constructor()` chaining is unchanged.
- [2026-04-22] **`Elgg\Di\ServiceFacade` trait removed in Elgg 4.x** — it provided `instance()` static method (`elgg()->{name()}`). Replace with manual `public static function instance(): self { return elgg()->get(static::name()); }`. Use `self` not `static` as return type for PHP 7.4 compat.
- [2026-04-22] **Elgg 4.x view system cache is stale after per-plugin Docker install** — `view_locations` cache is built during `bootCore()` called in the install script, BEFORE the plugin is activated. PHPUnit test `setUp()` calls `boot->boot()` which re-loads cached view locations, wiping any manually-registered views. Fix: after `registerPluginViews($plugin->getPath())` in test bootstrap, call `cacheConfiguration(_elgg_services()->serverCache)` to persist the corrected view map.
- [2026-04-22] **Elgg 4.x hook handlers called with single `\Elgg\Hook` arg** — old `__invoke($hook, $type, $return, $params)` signature gets `ArgumentCountError: Too few arguments (1 passed)`. Change to `__invoke(\Elgg\Hook $hook)` and use `$hook->getValue()` for the return value.
- [2026-04-22] **Hook handler class registered by class name must have `__invoke()`** — registering `ExtractTokensFromText::class` when the class has only a static method `extractTokens()` generates "Handler is not callable" warning. Register as `[ExtractTokensFromText::class, 'extractTokens']` instead.

- [2026-04-22] **`update_entity_last_action()` does not exist in Elgg 4.x** — calling it from `ElggEntity::save()` overrides causes a fatal "Call to undefined function". Remove the call entirely; Elgg 4.x updates `last_action` automatically. If you need to update a container's last_action, update the container entity's metadata directly.

- [2026-04-23] **`Elgg\Di\DiContainer` in Elgg 4.x uses PHP-DI v6** — the old 3.x helper methods `setValue()`, `setFactory()`, `setClassName()` are gone. Plugins with `class Plugin extends DiContainer` must: (1) call `parent::__construct()` before any `set()` calls (otherwise `$this->definitionSource` is null and `setDefinition()` fatals), (2) replace `setValue($k,$v)` with `set($k,$v)`, (3) replace `setFactory($k, Closure)` with `set($k, Closure)` — PHP-DI v6 wraps closures in `FactoryDefinition` (lazy), (4) replace `setClassName($k, ClassName::class)` with `set($k, function() { return new ClassName(); })`. The old `Plugin $p` factory arg in type-hint won't autowire to the Plugin itself; use `use ($this)` or capture in a local var instead.

- [2026-04-23] **`hypeJunction/acl_builder_api` is not on packagist and not in any maintained Elgg 4.x plugin** — `hypeJunction\Access\EntitySet` (used in older hypeinbox/hypeattachments) is from this package. The class is not available in the bodyology stack's Elgg 4.x environment. Plugins that use it must either inline the minimal array-set logic or add a local stub.

- [2026-04-24] **Elgg 5.x simplecache URL format uses a real timestamp** — `/cache/<timestamp>/default/elgg.css`, NOT `/cache/0/default/elgg.css`. Any Playwright test that navigates to `/cache/0/...` will get a 410 Gone response. Fix: extract the `<link>` `href` from the page, grab `url.pathname`, and navigate to that. Also: the href uses the Elgg `wwwroot` (e.g. `http://localhost:9580/...`), so extract pathname only and let Playwright resolve it against baseURL (`http://elgg`) to stay within the Docker network.

- [2026-04-30] **`elgg/sniffs` phpcs standard path** — `elgg/sniffs` installs its ruleset at `vendor/elgg/sniffs/src/` (not `vendor/elgg/sniffs/`). Register with `vendor/bin/phpcs --config-set installed_paths /var/www/html/vendor/elgg/sniffs/src`. After this, `--standard=Elgg` works. This is done at Docker image build time in all infra templates (elgg3–elgg7). The `elgg/sniffs` package has no stable release — always pin as `dev-master` with `minimum-stability: dev`.

- [2026-04-30] **Installed elgg-migrate skill is a symlink to dev source** — `~/.agents/skills/elgg-migrate` now symlinks to `/home/ismayilkhayredinov/Data/elgg-migrate/skills/elgg-migrate`. Any changes to the dev source are immediately live. The old stale copy was backed up to `~/.agents/skills/elgg-migrate.bak`.

- [2026-04-30] **Plugin with its own `vendor/elgg/elgg` shadows the main Elgg in tests** — Composer registers autoloaders with `prepend=true`, so loading a plugin's `vendor/autoload.php` AFTER the main Elgg one causes the plugin's Elgg classes to prepend themselves and win. Symptom: `PluginException` with wrong plugin paths like `mod/hypefaker/mod/hypefaker/`. Fix: in `tests/bootstrap.php`, load the plugin's vendor autoloader FIRST, then the main Elgg's. The main Elgg prepends last and wins the `Elgg\` namespace while the plugin's vendor still provides Faker\ etc.

- [2026-04-30] **`get_user_by_username()` removed in Elgg 6.x** — use `elgg_get_user_by_username()`. This affects Docker install scripts that create test users. The 5.x version still ships this legacy alias but 6.x does not.

- [2026-04-30] **ES module jQuery import in Elgg 6.x** — use `import $ from 'jquery'` (no path needed — Elgg 6.x registers jQuery as a module for ESM). The old `require('jquery')` AMD pattern is gone.

- [2026-04-29] **Elgg 6.x `view_extensions` requires nested-array format** — `registerViewExtensions()` iterates `foreach($extensions as $ext => $spec)` where `$spec` must be an array. In 5.x this was a flat string `'base' => 'ext'`. In 6.x use `'base' => ['ext' => []]`. Using the old format generates a PHP Warning which triggers `Plugins::init()` auto-disable (removes `active_plugin` relationship), causing `getAllSettings()` to return `[]` via the new `isActive()` guard added in 6.x.
- [2026-04-29] **Elgg 6.x drops AMD/RequireJS entirely** — `elgg_require_js()` removed; use `elgg_import_esm()`. All JS must be ES modules (`import/export`). Remove `define(function(require){...})` wrappers and convert `var x = require('mod')` to `import x from 'mod'`.

- [2026-04-29] **Docker compose db container missing from network after pool-exhausted restart** — when Docker's address pool is exhausted, `docker compose up -d` fails to create the network. If you then prune networks and re-run `up -d`, Docker reuses the already-created containers WITHOUT re-attaching them to the new network. The db container starts (and is even "healthy") but the elgg container can't resolve `db` hostname. Fix: always run `docker compose down` (to REMOVE containers) before `up -d` after a failed pool-exhaustion error. Never rely on `up -d` alone to re-attach orphaned containers.
- [2026-04-29] **Pool exhaustion symptom**: `docker network ls` shows 28+ plugin networks from stale sessions. Run `docker compose -f <plugin>/docker/docker-compose.yml down` on 5-6 inactive stacks before starting a new one. Run `docker network prune -f` first (removes truly dangling networks).

- [2026-05-08] **Elgg 5.x `Elgg\Event` constructor requires 3 args** — `Elgg\Event::__construct(PublicContainer $dic, string $name, string $type)`. PHPUnit's `getMockBuilder(Event::class)->getMock()` fails with "Too few arguments" because PHPUnit calls `__construct()` with no args to create the mock. Always add `->disableOriginalConstructor()` when mocking `Elgg\Event` (and any other Elgg 5.x service class with required constructor args).

- [2026-05-08] **`disableOriginalConstructor()` on ElggEntity subclass mocks breaks `__get`/`__set`** — Without the constructor, `ElggEntity::initializeAttributes()` is never called, leaving `$this->attributes = []`. Any `__get`/`__set` call that tries to read metadata falls through to `getAllMetadata()` → `if (!$this->guid)` → triggers `__get('guid')` → re-entrancy protection → PHP "Undefined property" notice treated as PHPUnit error. Fix: do NOT use `disableOriginalConstructor()` on `ElggObject`/`ElggEntity` subclass mocks in Elgg integration tests — the default `ElggEntity::__construct(null)` only calls `initializeAttributes()` and is safe to call.

## Key Learnings (2026-05-09, 6.x→7.x batch B)

- [2026-05-09] **Elgg 7.x `RouteRegistrationService::generateUrl()` permanently nullifies route defaults** — when `generateUrl('route:name', ['param' => 'value'])` is called and `'value'` matches the route's configured default, the service calls `$route->setDefault('param', null)` on the live route object so the param appears explicitly in the URL. This permanently modifies the singleton route object. Subsequent calls to `$route->getDefault('param')` return `null` even though the route was declared with a non-null default. **PHPUnit consequence**: if test A calls `elgg_generate_url('default:search', ['search_type' => 'user'])` and test B runs after it and calls `elgg_get_plugin_from_id('site_search')->routes['default:search']->getDefault('search_type')`, it gets null instead of 'object'. Fix: read expected defaults directly from `elgg-plugin.php` config, not from the live route object.

- [2026-05-09] **Elgg 7.x `ElggPlugin::getAllSettings()` returns `[]` when plugin is inactive** — in Elgg 7.x, `getAllSettings()` explicitly early-returns `[]` when `!$this->isActive()`. Any test that calls `$plugin->setSetting(...)->getSetting(...)` without ensuring the plugin is active will silently get empty results. When upstream dep plugins (e.g. hypeprototyper, hypeapps) still use `start.php` (pre-4.x format), they cannot activate on 7.x, which cascades to block activation of plugins that depend on them. Fix: guard all such tests with `if (!$plugin || !$plugin->isActive()) { $this->markTestSkipped('...'); }`.

- [2026-05-09] **PHPUnit test `class_exists()` guard for dep-plugin classes in 7.x test stacks** — when a test asserts that field classes extending a base class from a dep plugin (e.g. `hypeJunction\Prototyper\Elements\AttributeField`) are loadable, and the dep plugin is not yet migrated to 7.x, `class_exists()` returns false and class autoloading fails. Fix: add `if (!class_exists(\DepPlugin\BaseClass::class)) { $this->markTestSkipped('dep not migrated'); }` before the assertion loop. The bootstrap.php autoloader only covers the plugin-under-test's own namespace.

- [2026-05-09] **Root-owned `tests/playwright/node_modules/` prevents branch checkout** — when a previous Docker container ran as root and created `node_modules/` via a bind mount into the repo, `git checkout` fails with "untracked working tree files would be overwritten". Since `sudo` may not be available, workaround: `git clone --branch migrate/elgg-7.x <remote> <temp-dir>` to get a clean working tree, then run orchestration from the temp dir. Always add `tests/playwright/node_modules/` to `.gitignore` in the plugin repo.

- [2026-05-09] **`notifications_mass_mail` 6.x→7.x**: No code changes needed beyond composer.json bump to `elgg/elgg ~7.0.0` / PHP `>=8.3`. The Laminas→Symfony Mailer rule (Rule 004) does NOT apply because the plugin uses Elgg's own notification service abstraction (`\Elgg\Notifications\NotificationHandler`) rather than Laminas classes directly. ## Key Learnings (2026-05-09, Seeder requirement)

- [2026-05-09] **Plugins owning entity types/subtypes/relationships MUST ship a `Seeder` class** extending `\Elgg\Database\Seeds\Seed` and registered on `elgg_register_event_handler('seeds', 'database', [Seeder::class, 'addSeed'])` in the plugin Bootstrap. The Seeder is reused as the canonical fixture source by `elgg-test-writer` integration tests, so divergence between test fixtures and the plugin's actual entity shape is not tolerated. Pure UI/utility/admin plugins (no persisted state) are exempt; the absence must be documented in ARCHITECTURE.md under a "Seeding" heading. Both `elgg-migrate/SKILL.md` (Phase 2 + Acceptance Gates) and `elgg-test-writer/SKILL.md` (Phase 3 + coverage checklist) carry this rule. Per-plugin follow-up tracked under epic created 2026-05-09.

- [2026-05-09] **Git release workflow: `git merge-tree --write-tree` bypasses working-tree conflicts for merge commits** — when `git merge --no-ff` fails due to root-owned untracked files or add/add conflicts that are resolvable by taking `theirs`, use `git merge-tree --write-tree [--allow-unrelated-histories] master migrate/elgg-7.x | head -1` to get the merged tree SHA, then `git commit-tree <tree> -p <master> -p <migrate> -m "chore: merge"` + `git update-ref refs/heads/master <sha>` to create the merge commit without touching the working tree. Works for all merge conflict types (add/add, unrelated histories, permission errors).

- [2026-05-09] **Release procedure for `images` plugin**: `images` master branch has unrelated history from the 2.x era. Use `git merge-tree --write-tree --allow-unrelated-histories master migrate/elgg-7.x` to get the fully resolved merged tree including both lineages, then create the merge commit via `commit-tree`.


- [2026-05-10] **Elgg 4.x menu views receive `PreparedMenu` not array** — `navigation/menu/default.php` and similar views receive an `Elgg\Menu\PreparedMenu` object as `$vars['menu']`. Calling `array_keys($menu)` causes a fatal. Use `foreach ($menu as $section)` where `$section instanceof MenuSection`, then `$section->getID()` and `$section->all()`. Always check `if (!$menu instanceof PreparedMenu) { return; }` first.

- [2026-05-10] **`elgg_get_loaded_js()` removed in Elgg 4.x** — replace with `elgg_get_loaded_external_resources('js', $location)` which returns objects with a `->url` property. The 'head'/'footer' location distinction is preserved. Any theme or plugin overriding `page/elements/foot.php` must be updated.

- [2026-05-10] **Elgg 4.x hook handler signature is a SINGLE object** — `register_hook_handler()` callbacks must accept one arg `\Elgg\Hook $hook`; use `$hook->getValue()`, `$hook->getParam('key')`, `$hook->getParams()`. The old 4-argument `($hook_name, $type, $value, $params)` causes fatal "Too few arguments" on first invocation. Scan ALL plugins' `classes/` directories for `__invoke($hook, $type,` before activating.
