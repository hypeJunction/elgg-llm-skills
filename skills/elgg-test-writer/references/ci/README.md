# Per-plugin CI templates

Reference GitHub Actions workflows for an Elgg plugin generated by
`elgg-test-writer`. They are **templates** — copy them into a plugin
repository at `.github/workflows/` (use `bin/scaffold-ci.sh` for a
deterministic copy), then commit. They run unmodified on standard
GitHub-hosted runners.

**Scope**: these workflows are forward-looking. They gate `main` /
`master` and PRs against future regressions. They are **not** part of
the migration validation path — migration work is gated locally by
`bin/verify-plugin.sh` against the per-plugin docker stack. Pushing
the workflows on a `migrate/*` branch is expected to produce
"completed/failure" runs with 0 jobs and 0s duration (the branch
filter rejects the push); that is a scheduling skip, not a real
failure. The first real execution happens on the first PR or after
merge to the default branch.

## What ships

| File | Purpose | Triggers |
|------|---------|----------|
| `tests.yml` | Boots `<plugin>/docker/docker-compose.yml`, runs PHPUnit, runs Playwright | push to main/master, pull_request |
| `lint.yml` | `php -l` matrix, `composer validate`, JSON parse, workflow YAML parse | push to main/master, pull_request |

## Design

CI re-uses the per-plugin docker stack the test-writer skill scaffolds
(`<plugin>/docker/`). The runner does **not** install PHP, MySQL, or
Elgg natively — `docker compose up` boots the same stack a developer
runs locally, so green CI = green local. There is no separate CI
install path to maintain.

## Job structure

`tests.yml` has two independent jobs:

- **phpunit** — runs only when both `docker/docker-compose.yml` and
  `tests/phpunit.xml` exist. Boots the stack, waits for
  `/var/www/html/.elgg-installed`, installs PHPUnit into Elgg's
  vendor, clones `elgg_*` tables into the `c_i_elgg_*` test prefix,
  and runs the plugin's PHPUnit config.
- **playwright** — runs only when `tests/playwright/package.json`
  exists. Boots the same stack, then runs the `node` profile service
  with `npm ci && npx playwright test`. Uploads the HTML report as an
  artifact.

`lint.yml` has four independent jobs:

- **php-syntax** — `php -l` matrix across PHP 7.4 / 8.1 / 8.3 on every
  tracked `.php` file outside `vendor/` and `node_modules/`. Drop rows
  that don't apply to the plugin's target version.
- **composer-validate** — `composer validate --strict
  --no-check-publish` against `composer.json`.
- **json** — every tracked `.json` file parses.
- **workflow-yaml** — every workflow YAML file parses.

## PLUGIN_ID resolution

Both `tests.yml` jobs need `PLUGIN_ID` to drive the docker stack. They
resolve it in this order, matching `bin/scaffold-docker.sh`:

1. `composer.json` `extra.elgg-plugin.id`
2. `composer.json` `name`, lowercased basename after `/`
3. Repo basename, lowercased

The resolved value is written to `docker/.env` inside the runner — the
file is gitignored, so it doesn't conflict with a developer's local
`docker/.env`.

## What you may need to customize

- **PHPUnit version** — the workflow installs `phpunit/phpunit:^9.6`
  (correct for Elgg 3.x/4.x on PHP 7.4). Bump to `^10.5` for Elgg
  5.x+ on PHP 8.1+.
- **PHP version matrix in `lint.yml`** — drop the rows that don't
  apply to the plugin's `composer.json` `require.php` constraint.
- **Branches** — defaults are `main` / `master`. Add release branches
  if the plugin uses `4.x`, `5.x`, etc.

## What the workflows do **not** do

- No coverage upload, code climate, or third-party test reporters.
- No release / publish flow.
- No deploy.
- No matrix across multiple Elgg majors — each plugin's docker stack
  pins one Elgg major. Test against a different major by changing
  `--elgg-version` when scaffolding, not in CI.

These are deliberate — keep CI small, copyable, and readable.

## Installing into a plugin

```bash
$SKILL/bin/scaffold-ci.sh                               # uses cwd
$SKILL/bin/scaffold-ci.sh --plugin-dir=/abs/path        # explicit
$SKILL/bin/scaffold-ci.sh --force                       # overwrite existing
```

The script writes:

    <plugin>/.github/workflows/tests.yml
    <plugin>/.github/workflows/lint.yml

Existing files are left alone unless `--force` is passed.

## Debugging a CI failure

Failures upload diagnostics as artifacts:

- `phpunit-diagnostics/` — `compose.log` (all containers) and
  `apache-error.log` from the elgg container.
- `playwright-report/` — Playwright HTML report (always uploaded).
- `playwright-diagnostics/` — `compose.log` on failure.

Reproduce locally with the exact same commands the workflow uses:

    PLUGIN_ID=<id> docker compose -f docker/docker-compose.yml up -d
    docker compose -f docker/docker-compose.yml exec elgg \
      vendor/bin/phpunit --configuration mod/$PLUGIN_ID/tests/phpunit.xml --no-coverage
